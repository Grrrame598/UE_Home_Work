Инструкция по работе с GitLab и сдаче домашних заданий

Для сдачи домашних работ на проверку в рамках курса мы будем использовать GitLab — онлайн-сервис для хранения и управления кодом. Инструкцию по установке и подготовке всего необходимого софта ищи ниже.

Git Flow

Инструкция по работе с GitLab и сдаче домашних заданий

1. Введение

Git — это система контроля версий, которая позволяет отслеживать изменения в коде и работать над проектом в команде. В рамках курса мы будем использовать GitLab — онлайн-сервис для хранения и управления кодом.

Вы можете использовать консольную версию Git, но также допускается работа с графическими клиентами, такими как Sublime Merge, Fork, TortoiseGit и другие. В реальной практике чаще всего используются графические клиенты, так как они упрощают работу с репозиторием и позволяют быстрее выполнять операции, такие как коммиты, создание веток и разрешение конфликтов.

2. Установка Git

Git необходимо установить на ваш компьютер, чтобы работать с репозиториями.

Установка на Windows

1. Перейдите на официальный сайт и скачайте последнюю версию установщика.  

2. Во время установки оставьте параметры по умолчанию, за исключением опции Windows Explorer integration, которую нужно включить для удобного доступа к Git Bash.

3. После установки откройте терминал (Git Bash, PowerShell или командную строку) и выполните команды

git -v
git lfs -v

Если отобразилась версия Git, значит установка прошла успешно.

Установка на macOS и Linux

На macOS Git установлен по умолчанию. Для обновления используйте команду:

brew install git

На Linux (Ubuntu/Debian) установите Git с помощью команды:

sudo apt update && sudo apt install git

3. Основные термины в Git и GitLab

Прежде чем приступать к работе, важно понимать основные понятия:

  • Репозиторий — это хранилище проекта, в котором хранятся все файлы и их изменения.
  • Ветка (Branch) — параллельная версия кода. Главная ветка обычно называется main.
  • Коммит (Commit) — зафиксированное изменение в коде.
  • Push — отправка изменений в удалённый репозиторий.
  • Pull — обновление локальной копии проекта последними изменениями.
  • Merge Request (MR) — запрос на объединение вашей ветки с основной.
  • Конфликт (Merge Conflict) — ситуация, когда изменения в разных ветках затрагивают один и тот же файл.
  • Git LFS: По умолчанию Git оптимизирован работать с текстовыми файлами. Но все файлы с которыми вы будете работать в редакторе unreal engine являются бинарными. LFS это расширение для Git, которое оптимизирует работу с большими файлами

3. После этого нужно заполнить информацию о своей компании. Пример заполнения (можно заполнять полностью аналогично):

Создание репозитория

1. После регистрации GItLab предложит создать новый репозиторий

2. В поле Project Name введите название проекта (желательно совпадающее с названием игры на Unreal Engine).

Добавление преподавателя в проект

2. Пригласите пользователя XYZTeacher и обязательно выбрать параметр Developer в поле Select maximum role.

  1. В левой части страницы вашего репозитория нажмите Manage→ Members
  2. Нажмите Invite Members.
  3. Введите XYZTeacher и выберите роль Developer.
  4. Нажмите Invite.

5. Клонирование репозитория

1. Откройте страницу репозитория и скопируйте или HTTPS ссылку.

2. В терминале выполните команду:

git clone <URL вашего репозитория>

Пример финальной команды:

git clone https://gitlab.com/xyz1360706/GameCode.git

3. При первом клонировании может потребоваться авторизация через браузер.
Если выполнять clone через консоль, то откроется окно в котором нужно нажать “Sign In with your browser”.

Выполнить авторизацию в браузере и нажать кнопку “Authorize Git Credential Manager”.

6. Настройка репозитория для UE

После того как вы склонировали к себе репозитрий его необходимо настроить для использования с unreal engine проектом.

Для этого нужно:

1. Скачать и добавить в корень репозитория файл .gitignore. Этот файл добавляет в игнор git временные файлы которые генерирует unreal engine и IDE во время работы.

2. Добавить в корень репозитория файл .gitattributes.
Файл .gitattributes активирует расширение git lfs которое оптимизирует работы гита с большими/бинарными файлами.

После этого нужно перенести все файлы из вашей папки с ue проектом (или создать его) в корневой папке вашего репозитория.

7. Порядок сдачи домашнего задания

Что такое Merge Request и зачем он нужен?

Merge Request (MR) — это запрос на объединение изменений из одной ветки в другую. Это основной инструмент для работы в команде и проверки кода перед добавлением его в основную ветку. В рамках курса MR будет использоваться для проверки ваших домашних заданий. Преподаватель сможет оставить комментарии и запросить исправления, если это необходимо. После одобрения Merge Request изменения будут добавлены в основную ветку проекта.

Почему важно создавать отдельные ветки для домашних заданий?

Создание отдельных веток для каждой домашней работы помогает структурировать работу и избежать путаницы в коде. Это удобно, потому что:

  • Изолированность изменений — работа над новым заданием не затрагивает основной код проекта.
  • Легкость исправлений — если преподаватель попросит внести правки, можно просто обновить ветку, не влияя на другие задания.
  • Чистота истории коммитов — каждое задание имеет свою ветку, что делает историю коммитов более понятной.
  • Безопасность кода — ошибки в новой функции или механике не попадут в основную ветку до полного одобрения преподавателем.

7.1. Создание новой ветки

Перед началом выполнения задания создайте новую ветку, чтобы изолировать изменения:

git checkout -b Homework1

7.2. Выполнение задания и отправка изменений

1. После внесения изменений зафиксируйте их командой:

git add .
git commit -m "Homework 1 completed"

2. Отправьте изменения в репозиторий:

git push origin Homework1

7.3. Создание Merge Request (MR)

1. Откройте страницу репозитория на GitLab.

2. В разделе Code выберите Merge Requests → New Merge Request.

3. В Source branch выберите вашу ветку (Homework1). В Target branch выберите main.

4. Заполните основную информацию о MR:
ᅠ a. В поле Title укажите название (например, Homework 1).
ᅠ b. В поле Description опционально можно комментарий для преподавателя. Либо оставить это поле пустым
ᅠ c. В поле Assignees нужно нажать кнопку “Assign to me”
ᅠᅠ i. Это поле указывает на того кто ответственен на создание MR
ᅠ d. В поле Reviewers выберите преподавателя XYZTeacher.
ᅠᅠ i. Reviewer это человек который ответственен за проверку изменений в вашем MR

5. Нажмите Create Merge Request.

7.4. Отправка Merge Request на проверку

1. Скопируйте URL созданного MR.

2. Вставьте ссылку в форму сдачи на платформе XYZ.

7.5. Внесение исправлений

Если преподаватель оставил комментарии с просьбой исправить код:

1. Внесите изменения.

2. Зафиксируйте их командой:

git add .
git commit -m "Fixed issues in Homework 1"
git push origin Homework1

Изменения автоматически обновятся в том же MR.

7.6. Завершение Merge Request

Если задание принято:

1. Нажмите Merge на странице MR в GitLab.

2. Переключитесь на main и обновите локальный репозиторий:

git checkout main
git pull origin main
